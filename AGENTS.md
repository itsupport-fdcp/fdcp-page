# FDCP Drupal Page Snippets

This repo holds **standalone HTML snippets** that get pasted into Drupal's
CKEditor (Basic Page → Full HTML text format). Each file is a self-contained
unit: inline `<style>`, inline `<script>`, no external bundles, no build step
on the Drupal side. Local files here = exactly what lands in the page body.

## Drupal CKEditor constraints — read before editing

These are the gotchas the existing code already works around. Keep them in
mind when adding new markup.

1. **No `<template>` element.** Drupal's HTML filter strips the *children* of
   `<template>` at render time. All three sheet-driven pages build cards from
   a JavaScript **string** (`CARD_HTML = [...].join("")`) instead — preserve
   that pattern.
2. **No external CSS or JS files.** Everything ships inline in the snippet.
   Tailwind is already loaded by the Drupal theme, so `class="..."` Tailwind
   utilities work without any `<script src="cdn.tailwindcss.com">`. Local
   previews use a CDN block clearly marked `LOCAL-PREVIEW ONLY` — delete that
   block before pasting (or leave it; it's redundant but harmless).
   **One sanctioned runtime exception:** the Stories viewer (`gallery.html`
   + `homepage-stories-snippet.html`) lazy-injects `hls.js` from a CDN the
   first time an HLS (`.m3u8`) story video is opened — see `ensureHls()`. It
   is *not* a page-load `<script src>`; the tag is created on demand and
   memoized, so non-video visitors never download it and Safari/iOS skip it
   entirely (they play HLS natively). Keep it lazy — don't hoist it to a
   static `<script src>` in the head.
3. **Drupal's compiled Tailwind is a subset.** It does **not** include
   `grid-cols-7` and several arbitrary-value utilities the calendar relies
   on. The calendar layout is hard-defined in a `<style>` block at the top of
   `upcoming-events.html` using `!important` as a specificity safety belt.
   Don't remove that block thinking Tailwind has it.
4. **Empty inline elements get stripped.** Drupal's filter removes "empty"
   `<span>`/`<p>`. When something must start empty, give it a placeholder
   (`—`, `&nbsp;`) so the filter keeps the element. See the location row in
   `event-details.html`.
5. **Critical layout styles should be inline (`style="..."`).** Anything that
   *must* render correctly even if the surrounding theme has unexpected CSS
   should be inlined. The calendar pills, modal, and toolbar are inlined for
   this reason — JS also re-applies them in `applyBaseStyles()` as a belt-
   and-braces guard against the filter dropping a `<style>` rule.
6. **Drupal wrappers may add top spacing.** `killTopSpacing()` walks up from
   `#main-content` and zeroes `margin-top` / `padding-top` so the snippet
   sits flush against the site header. Keep using it on full-page snippets.
7. **`!important` is intentional in `<style>` blocks.** It protects against
   Drupal's theme cascade. Don't strip it on cleanup passes.
8. **Drupal *blocks* strip more than Basic Pages.** When a snippet is pasted
   into a custom Block (e.g. the homepage's "Upcoming Event" region) instead
   of a Basic Page, the filter is stricter: the entire `<style>` block can
   be dropped, class attributes can disappear, and semantic elements like
   `<section>` and `<nav>` can be unwrapped to their text content. Confirmed
   symptom: stats/cards/pagination rendered as plain text with no styling.
   When that happens, the fix is always the same — **inline every critical
   style** on the element itself via `style="..."`.
9. **Use plain `<div>` for everything structural.** Avoid `<section>`,
   `<nav>`, `<article>`, `<aside>` in snippet markup — they may be stripped
   by block-context filters. The `aria-label` on a `<div role="...">` gives
   you the same accessibility without the risk.
10. **Tailwind utilities not in the compiled subset** (verified missing on
    the live Drupal install): `self-end`, `self-start`, `flex-col-reverse`,
    `gap-10`, `gap-32`, and most arbitrary-value classes like `lg:gap-32`.
    Rule of thumb: if a CSS property *must* be applied, write it inline as
    `style="align-self:flex-end;margin-left:auto;..."`. Treat Tailwind
    classes as nice-to-have progressive enhancement on top of inline styles.
11. **JS-generated elements: set inline styles per element.** Pagination
    buttons, chip active-state, month headers — anything created via
    `document.createElement(...)` and inserted at runtime must have its
    visual style applied via `el.setAttribute("style", "...")` or
    `el.style.cssText = "..."`. Class-based theming alone fails when Drupal
    has stripped the `<style>` block. The `renderPagination()` function in
    `upcoming-events.html` uses module-scoped `PAGE_BTN_BASE` / `_ACTIVE` /
    `_DISABLED` constants for this — match that pattern for any new
    rendered control.
12. **State toggles swap inline styles, not just classes.** When a button
    flips between active/inactive (chips, pagination current page, etc.),
    the JS must rewrite the `style` attribute, because a class swap won't
    visually flip anything if the `.fdcp-chip-active` CSS rule never
    arrived. See `applyChipStyle(btn, active)` in `upcoming-events.html`.
13. **`background-clip:text` with `-webkit-text-fill-color:transparent`
    is fragile** under aggressive filters. Stripping the fill-color rule
    leaves invisible-on-white text. If you want gradient text, always pair
    it with a solid `color: #580076` fallback so the text remains readable
    even when the gradient clip doesn't apply. The stats band numbers in
    `upcoming-events.html` use this pattern.
14. **Calendar week rows must be viewport-aware.** The week grid uses a
    fixed `grid-template-rows` set inline by `renderCalendar()`. On mobile
    (`window.innerWidth <= 768`) the function drops `VISIBLE_SLOTS` from 3
    to 2 and shrinks each row so the `+N more` button never overflows into
    the next week's cell (which is capped at 60 px by the mobile CSS).
    Don't hardcode the desktop values — read `isMobile` at the top of the
    function. Currently lives only in `upcoming-events.html`.
15. **Basic Page snippets get wrapped in `<article class="card mb-8">`.**
    Drupal wraps the pasted node body in `article.card mb-8 > .card-body >
    .prose`. The `mb-8` adds **32px of margin below your whole snippet**,
    which opens a dead gap (a strip of page-bg `#F8F8F8`) between your last
    section and the site footer. **This wrapper does not exist in local
    preview**, so the gap only appears on the live Drupal page — a file that
    looks flush locally can still have the gap. Fix from *inside* the
    snippet: put `margin-bottom:-2rem` (inline) on the snippet's last
    top-level section so it pulls flush against the footer. See the
    `MEET THE MANAGEMENT` gradient `<div>` in `about-us.html`. (If the theme
    ever changes that wrapper's `mb-8`, update the `-2rem` to match.) Verify
    the real gap on the live page, not the local file — measure
    `footer.getBoundingClientRect().top` vs the section's `bottom`.
16. **Overriding the global theme header (transparent + white).** The site
    header is rendered by the theme *outside* the pasted snippet, but a snippet
    that only lives on one page can still reach and restyle it — and that scope
    is automatically limited to that page. Key facts (verified by curling the
    live pages):
    - The header is **not** a `<header>`/`.site-header`. It's an Alpine
      `<nav class="fixed top-0 z-50 w-full">` whose classes are re-bound on
      scroll via `:class`. Target `nav.fixed.top-0`.
    - Interior/Basic pages render it light:
      `atTop ? 'bg-[#F8F8F8] text-black' : 'bg-white shadow-md'`, black logo
      (`fdcp-logo-update-black.webp`). The custom about-us page renders it
      `atTop ? 'bg-transparent text-white' : 'bg-black text-white shadow-md'`,
      white logo (`fdcp-logo-update-white.webp`).
    - Because Alpine rebinds `class`, **class-based overrides get clobbered** —
      override with **inline styles** (`el.style.setProperty(..., 'important')`)
      plus a few `!important` CSS rules. Inline styles survive `:class`.
    - Forcing `color:#fff` can turn a `currentColor`-based border/outline white,
      leaving a white box framing the header. Fix:
      `border-color:transparent;outline:none;box-shadow:none` on
      `nav.fixed.top-0` **and** its `*` descendants.
    - On a Basic Page the header floats over Drupal's white `article.card`
      chrome (constraint #15) / the theme's `#main-content` top padding (a
      ~112px `#F8F8F8` strip above the hero), so white nav text would sit on
      white at the top. A `#fdcp-header-backdrop` colour filler covers it.
      **It must be `position:absolute` (in the scrolling flow), NOT `fixed`,
      and always visible — do not toggle its `display` per scroll frame.** An
      earlier version made it `fixed z-40` and toggled `display:none`/`block`
      on `atTop` from the `scroll` handler; on a *fast* scroll the compositor
      runs a frame ahead of the JS, so there was a frame with the nav still
      transparent while the backdrop was already hidden → the white strip
      **flashed** through. As plain absolute content the filler just scrolls
      off with the page (the solid black header covers that strip anyway), so
      there is no per-frame race and no flash. Verified on the live test page
      `/about12345`. Size it `max(heroTopGap, navHeight)`; keep `z-index:1`
      (above the `#F8F8F8` page bg, below the header's `z-50`).
    - Reusable, configurable copy of all this lives in
      [transparent-header-snippet.html](snippets/transparent-header-snippet.html)
      (CONFIG block: `BACKDROP_COLOR`, `HERO_SELECTOR`, `WHITE_LOGO`). It is
      also inlined at the top of `about-us.html`'s body.

## Brand styling

Used consistently across every file — match these when adding new UI.

| Token | Value | Use |
| --- | --- | --- |
| Purple | `#580076` | Primary brand, gradient start, hover accents |
| Magenta | `#E200A9` | Brand accent, "today" marker, gradient end |
| Gold | `#FFCC00` | Cinematheque alt-program accent |
| Amber | `#CC8500` | Cinematheque alt-program accent (darker) |
| Off-white bg | `#F5F2FF` | Soft purple-tinted panel background |
| Page bg | `#F8F8F8` | Cinematheque page background |

**Section backgrounds: default to `transparent` (or `#F8F8F8`).** The site's
page background is `#F8F8F8`, so a snippet section with its own tinted
background (e.g. `#F5F2FF`) visibly clashes with the sections around it.
Give snippet wrappers `background:transparent` so they inherit the page bg
and always match neighbors; only use `#F5F2FF` for deliberate inner panels,
never for a full-width section wrapper. (User-requested rule, from the
SocialEmbed.html background fix.)
| Muted text | `#6b7280` / `#536471` / `#7C7C7C` | Secondary text, icons |
| Card border | `#e5e7eb` | Default 1px card outline |

Primary gradients (used on titles, CTAs, date pills, hero accents):

- Main: `linear-gradient(90deg,#580076 0%,#E200A9 100%)`
- Vertical: `linear-gradient(180deg,#580076 0%,#E200A9 100%)`
- Cinematheque alt: `linear-gradient(135deg,#CC8500 0%,#FFCC00 100%)`

Typography:

- Body: Poppins (Cinematheque imports it via `@import` from Google Fonts).
  Drupal-side pages inherit the theme's font stack.
- Display: Oswald (Cinematheque only).
- Headings on event pages use Tailwind sizing — `text-[40px] lg:text-[72px]`
  for hero, `text-[55px]` for section titles.

Naming conventions:

- IDs are prefixed `fdcp-` (e.g. `fdcp-cal-grid`, `fdcp-events-container`).
- Cinematheque uses a `cc-` (cinematheque) prefix on every class.
- `data-field="..."` attributes mark fields populated by JS from sheet rows.
  When you add a new field to `CARD_HTML`, populate it via `setText(node,
  "fieldname", value)` or `node.querySelector('[data-field="..."]')`.

## Google Sheets data source (3 of the 4 pages)

- Source sheet: `15RKI11nZfI2fPtjDS_Hi1aAhJyKPO9bz7Dtb5cDrCW0`
- Fetched as **HTML** (not CSV) via the gviz endpoint with `tqx=out:html`
  and `sheet=ALL` — the ALL tab aggregates every division (AFD, COMMS,
  FESTIVALS, etc.). The HTML format preserves bold/italic/underline/links
  typed in the sheet for the detail page; plain-text consumers (listing
  cards, calendar pills) read text via `cellToText()`.
- Shared cache key: `fdcp.events.v4` in `localStorage`. All three pages
  read/write the same key so paint is instant on every return visit. **Bump
  the version suffix (`v4` → `v5`) if you change the row schema** — old
  cached payloads will then be ignored instead of crashing the renderer.
- Stale-while-revalidate: cached rows paint immediately, a background fetch
  runs, and the DOM only re-renders if the FNV-1a hash of the new response
  differs. `attachFocusRevalidate()` re-runs the fetch when the tab regains
  focus (throttled to once per 60s).
- Rich-text columns are scrubbed through `sanitizeRichHTML()` against a
  small allowlist (`B, STRONG, I, EM, U, S, STRIKE, SUB, SUP, BR, SPAN,
  FONT, A`) before being written to the DOM.

### Stories video media (`gallery.html` + `homepage-stories-snippet.html`)

The Stories viewer reads the **`FDCP STORIES`** tab (not the `ALL` tab the
event pages use). `parseStoriesGviz()` matches columns by keyword — header
text is lowercased, then located by substring: **Category/Group**, **Caption**,
**Photo Link**, **Video Link / YouTube**, **IsActive** — and merges Photo Link
+ Video Link into one newline-joined list. `parseStoriesSheet()` (and the
homepage's parser) then classify each URL:

- **YouTube / Vimeo / Google Drive** → `iframe` asset (embedded player).
- **Direct video files** (`.mp4 .mov .webm .m4v .ogg`) → native `<video>`.
- **HLS** (`.m3u8`) → native `<video>` with **selectable quality**. Put a
  single `.m3u8` *master* playlist URL in the **Video Link** column (it already
  references every bitrate rendition); the player reads the resolutions from
  the manifest at runtime. On Chrome/Edge/Firefox a ⚙ gear menu (built in
  `buildQualityMenu()`) lists **Auto** + each height (`1080p`, `720p`…); on
  Safari/iOS the browser plays HLS natively with its own adaptive bitrate and
  **no gear** (JS can't pin a level there reliably). `hls.js` is lazy-loaded —
  see CKEditor constraint #2. The gear sits top-right on desktop and
  **bottom-right on mobile** (`window.innerWidth <= 900`) so it never collides
  with the close (✕) button, which is top-right on mobile. (Verified against a
  6-rendition stream: the menu shows Auto + 1080/720/540/432/360/270p,
  switching works, and the hls.js instance is torn down on every asset change
  and on close.)

**HLS story thumbnails are auto-captured.** An HLS-only story (no image in
Photo Link) has no static thumbnail, so the strip card + sidebar circle would
otherwise be a blank dark `#1a1a1a` box. `captureHlsFrame()` lazily grabs one
frame from the `.m3u8` via hls.js + `<canvas>` — **only** once the card scrolls
into view (`observeHlsCovers()` + `IntersectionObserver`), pinned to the lowest
rendition, downscaled to ~360px and JPEG-compressed (≈3 KB) by
`frameToCompressedDataURL()`, and cached per URL (`HLS_FRAME_CACHE`) so it runs
once and is reused by both the card and the circle. **Requires the stream to be
CORS-enabled** (`Access-Control-Allow-Origin` on the S3 bucket / CloudFront) —
a tainted canvas throws on `toDataURL`, capture resolves `null`, and the card
falls back to the dark box. A **Photo Link** still wins over capture (faster,
no decode), so prefer one when you have it. `isHls()` / `isVideo()` (extended to
match `.m3u8`) gate all of this and **must stay identical in both files** (the
viewer is implemented twice; see constraint #1 and the two-copies note in
working memory).

Configuration that changes per-deployment lives in a `// === CONFIG ===`
block at the top of each page's `<script>`:

- `SHEET_SRC` — gviz URL (keep `sheet=ALL` and `tqx=out:html`).
- `DETAIL_URL` — alias of the detail page (`/event-details` by default).
- `LIST_URL` — alias of the listing page (used by the detail page's back link).
- `CACHE_KEY` — bump version when the row schema changes.

## Cinematheque (`build.py`)

- Run from the repo root: `python build.py`. Reads `schedule.json` and writes
  `cinematheque.html`. `staticcinemaschedule.json` is a reference shape only
  — `build.py` reads `schedule.json`, which is **not** checked in.
- Schedule row shape: `{ date, dateISO, day, location, time, film, program,
  admission }`. `location` ∈ {`Manila`, `Negros`, `Iloilo`, `Davao`}.
- Editor-tunable constants near the top of the `<script>` block:
  - `MONTH_FILTER` — `"YYYY-MM"` to show one month, `""` to show all.
    Also controls the hero-image folder: `/sites/default/files/<MONTH_FILTER>/`.
  - `LOC_IMAGES` — maps each location to a `.webp` filename (without
    extension) inside the month folder.
  - `_siteFilmLinks` — normalised film title → Google Site page. A Manila row
    whose film is in the map gets a "View Details" CTA; every other row
    (all regions, and Manila films with no Site page) shows "Walk-in Only".
  - `CALENDAR_URLS` — per-location full-calendar link (set `""` to hide).
  - `ALT_PROGRAMS` — locations rendered with the amber/gold gradient
    instead of purple/magenta.

## Asset paths

- Drupal serves uploaded images at `/sites/default/files/<YYYY-MM>/...`.
  The convention is to drop monthly hero images into a folder named after
  the active `MONTH_FILTER` (e.g. `/sites/default/files/2026-05/manila.webp`).
- Theme-bundled images live at `/themes/custom/fdcp_theme/assets/images/...`
  (e.g. the calendar hero background).
- The `assets/` folder in this repo is **local-preview only** — the live
  page reads from Drupal's file system, not from this repo.

## Working in this repo

- Edit the HTML files directly — they're meant to be opened in a browser
  for local preview, then pasted into CKEditor verbatim.
- Open `upcoming-events.html` / `event-details.html` / the homepage snippet
  via `file://` or a local static server to preview. The "LOCAL-PREVIEW
  ONLY" block at the top loads Tailwind via CDN so the layout works
  outside Drupal.
- For Cinematheque, edit the template inside `build.py` (not the generated
  `cinematheque.html` — your changes there get clobbered next build).
- When pasting into CKEditor: switch the editor to "Source" view, paste the
  full file contents, save. Don't switch back to WYSIWYG before saving — it
  can re-mangle the HTML.
- The text format must be **Full HTML**. Restricted/Basic HTML formats will
  strip the `<style>`, `<script>`, and most of the structural markup.
